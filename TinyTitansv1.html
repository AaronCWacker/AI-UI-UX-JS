📚 Pocket glossary
Model
A math system that makes predictions.
Dataset
A collection of examples to learn from or test with.
Token
A unit of text. Here, one character.
Embedding
A learned list of numbers representing a token.
Weight
An adjustable number inside the model.
Hidden state
A short numerical memory of earlier characters.
Training
Changing weights to reduce prediction error.
Epoch
One pass through the practice examples.
Loss
A score for prediction error. Lower is better.
Gradient
A clue about how a weight affects loss.
Backprop
Calculating those clues backward through the model.
Optimizer
The rule that updates weights. Here: Adam.
Learning rate
The size of the optimizer's adjustment.
Validation
Checking examples excluded from weight updates.
Overfitting
Learning practice examples without learning useful patterns.
Inference
Using trained weights to make a prediction.
Agent
A program that carries out steps using models or tools.
ONNX
A standard for sharing model calculations and weights.
👩‍🏫 A 20-minute teaching challenge

0–3 minutes: Predict what the model will answer before training. Can random weights explain AI?

3–8: Train the sample. Explain “epoch” and “loss” to a partner. Find one connection whose weight changed.

8–13: Test “training?” and then “why is the moon bright?”. Why might fluent words still be wrong?

13–18: Run the reviewers. Add a new practice example, keep a different question for validation, and compare a fresh run.

18–20: Export the model. Explain the difference between an app, a model, and its training data.

Exit ticket: “My model learned ___. My evidence is ___. One thing it still cannot do is ___.”

🔗 How this connects to bigger AI

Large language models also predict tokens, compare predictions with examples, and update weights. They commonly use transformers, much more data, and far more computing power. This lab uses a small recurrent network so you can inspect the process.

The supplied Python trainer fine-tunes existing Hugging Face models. This lab trains its own tiny model from scratch. Arbitrary .pth, Hugging Face, and ONNX files cannot be trained by this app.

For images, examples become pixels and targets might be labels or restored pictures. The same train → measure → improve cycle applies. A text model does not learn images.

CSV rules & a fair test

Headers: prompt,response, with optional split containing train or validation. Without a split column, the last 20% of rows become validation.

4–200 rows; prompts up to 80 characters, answers up to 120. Up to 128 distinct training characters. Text becomes lowercase and is trimmed. Quotes, commas, and quoted line breaks are supported.

Keep validation prompts different from practice prompts. Similar paraphrases are a gentle test; entirely new topics are a much harder test. Use examples you have permission to share, without personal details.

What changes during training?

Forward pass: characters travel through the network to predict the next character.

Loss: cross entropy measures how little probability the model gave the correct answer character.

Backpropagation: gradients travel backward through the sequence. Adam uses them to adjust weights.

Validation: we measure reserved examples without updating weights. If practice loss falls while validation loss rises, investigate overfitting.

How to run a useful experiment

Change only one thing: the examples, the learning rate, or the number of epochs. Start fresh for a fair comparison. Record the validation score and actual generated answers, not just the training score.

Repeatedly tuning against validation makes it less independent. Keep an extra final test set outside your tuning process.

Which format should I choose?

Model JSON: reload here, continue training, and keep optimizer state, examples, and learning history.

ONNX + tokenizer: use the learned calculations in another inference app. This export is one recurrent step; the receiving app must loop over characters and retain the hidden state.

App + model: an HTML copy with your checkpoint embedded. Opening it starts with your trained weights. The single file loads Three.js from a CDN; the provided site ZIP includes it locally.

Renaming .pth to .onnx does not convert a model. Architectures and input/output conventions must also match.
